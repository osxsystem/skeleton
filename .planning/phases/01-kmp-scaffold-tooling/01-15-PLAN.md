Approach A — system `gradle` command (use this if `gradle` is on PATH):
```bash

  --gradle-version 9.5.0 \
  --distribution-type bin \
  --gradle-distribution-url "https://services.gradle.org/distributions/gradle-9.5.0-bin.zip"
```

Approach B — use cached distribution if system `gradle` is not available:
```bash

if [ -n "$GRADLE_BIN" ]; then
  "$GRADLE_BIN" wrapper \
    --gradle-version 9.5.0 \
    --distribution-type bin \
    --project-dir "$(pwd)"
fi
```

Approach C — download Gradle 9.5.0 to a temp dir, then use it to generate the wrapper (fallback if neither A nor B is available):
```bash
TMPDIR=$(mktemp -d)

unzip -q "$TMPDIR/gradle-9.5.0-bin.zip" -d "$TMPDIR"
"$TMPDIR/gradle-9.5.0/bin/gradle" wrapper \
  --gradle-version 9.5.0 \
  --distribution-type bin \
  --project-dir "$(pwd)"
rm -rf "$TMPDIR"
```

  <action>
`build.gradle.kts:3` has `kotlin("jvm") apply false` with no version string. Gradle cannot resolve this plugin because it has no version and no catalog alias. The `:server` module uses `kotlin("jvm")` directly in its own plugins block, so this declaration in the root build cannot be removed — it must be expressed via the version catalog so it carries the `kotlin` version (2.3.21).

**Note:** If Task 1 pre-applied this fix as part of its prerequisite step, verify the changes below are already in place with the grep commands at the end, and skip the edits if they are already correct.

**Step 1: Add `kotlin-jvm` entry to `gradle/libs.versions.toml` [plugins] block**

Read `gradle/libs.versions.toml` and locate the `[plugins]` block. It currently ends with:
```toml
vanniktech-publish    = { id = "com.vanniktech.maven.publish",               version.ref = "vanniktech-publish" }
```

Append this line immediately after the `kotlin-serialization` entry (keep the JetBrains plugins grouped together):
```toml
kotlin-jvm            = { id = "org.jetbrains.kotlin.jvm",                  version.ref = "kotlin" }
```

The `kotlin` version ref is already defined in `[versions]` as `kotlin = "2.3.21"`. No new version entry is needed.

The final `[plugins]` block should have these three Kotlin plugin entries grouped together:
```toml
kotlin-multiplatform  = { id = "org.jetbrains.kotlin.multiplatform",         version.ref = "kotlin" }
kotlin-serialization  = { id = "org.jetbrains.kotlin.plugin.serialization",  version.ref = "kotlin" }
kotlin-jvm            = { id = "org.jetbrains.kotlin.jvm",                  version.ref = "kotlin" }
```

Read `build.gradle.kts`. Line 3 currently reads:

Replace it with:

Preserve the alignment spacing to match the surrounding lines. All other lines in `build.gradle.kts` remain unchanged.

**Step 4: Verify :server still resolves the plugin**

`:server/build.gradle.kts` declares `kotlin("jvm")` without a version in its own plugins block. In Gradle, when a plugin is declared `apply false` in the root, subprojects can apply it without specifying a version — the version is inherited from the root resolution. After the catalog alias change, the version is now provided by `libs.plugins.kotlin.jvm` (2.3.21). The `:server` subproject declaration `kotlin("jvm")` will resolve to the same version through Gradle's plugin management.

Run a quick configuration check:
```bash

```
