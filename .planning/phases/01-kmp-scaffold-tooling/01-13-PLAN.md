<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI gate → merge gate | CI is the trust boundary for code merging into main; a gate that exits 0 on failure is not a gate at all |
| libs.versions.toml → build scripts | Version catalog is the single source of truth for dependency coordinates; unused entries can be silently re-introduced by developers who see the entry and assume it is intentional |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | CI SKIE header gate (WR-05) | mitigate | Changing exit 0 to exit 1 means a broken XCFramework build or wrong output path will block the PR; no false-green SCAF-11 verification possible |
| T-13-02 | Repudiation | kotlinx-datetime in :shared-core | mitigate | Removing the catalog entry (not just the usage) prevents silent reintroduction; any future use requires an explicit catalog entry addition that will be visible in code review |
| T-13-03 | Denial of Service | XCFramework path check exits 1 prematurely | accept | The exit 1 only fires if the Gradle build task succeeds but emits to an unknown path — this is a real build problem that should block CI, not be silently skipped; accepted as intended behavior |
</threat_model>
