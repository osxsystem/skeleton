Replace the entire file content with:

```kotlin
package dev.viethung.showcase.di

import dev.viethung.core.di.coreModule
import dev.viethung.showcase.greeting.GetGreetingUseCase
import dev.viethung.showcase.greeting.GreetingRepository
import dev.viethung.showcase.greeting.GreetingRepositoryImpl
import dev.viethung.showcase.greeting.GreetingViewModel
import org.koin.core.context.startKoin
import org.koin.core.module.Module
import org.koin.dsl.module

/**
 * Showcase Koin module — registers all showcase-specific dependencies.
 *
 * Platform entry points call initKoin(platformModule) at app start.
 * initKoin() is the single canonical Koin initialization entry point for both platforms.
 *
 * GreetingRepositoryImpl is bound here in appModule (backed by AppDatabase from coreModule).
 * DatabaseDriverFactory is NOT bound here — the platform module provides it (platformModule on
 * Android, iosPlatformModule on iOS) so coreModule can resolve get<DatabaseDriverFactory>().
 */
val appModule = module {
    includes(coreModule)

    // CR-01 fix: bind GreetingRepository to its SQLDelight-backed implementation
    factory<GreetingRepository> { GreetingRepositoryImpl(get()) }
    factory { GetGreetingUseCase(get()) }
    factory { GreetingViewModel(get()) }
}

/**
 * Top-level Koin initialization entry point — used by iOS only.
 *
 * Android: SkeletonApp.onCreate() calls startKoin { ... modules(appModule, platformModule) }
 *          directly (NOT initKoin()) — `androidLogger` and `androidContext` are Android-only
 *          Koin extras that cannot live in shared commonMain code.
 * iOS:     AppKoinBridge.start() calls AppModuleKt.doInitKoin(platformModules: [iosPlatformModule])
 *          (SKIE maps Kotlin `initKoin` top-level fun → Swift `AppModuleKt.doInitKoin`; the
 *           `vararg platformModules: Module` parameter becomes `platformModules: [any KoinModule]`
 *           in the generated Swift overlay — verify exact signature in the XCFramework headers)
 *
 * CR-02 fix: platformModules parameter lets iOS supply its DatabaseDriverFactory binding.
 */
fun initKoin(vararg platformModules: Module) {
    startKoin {
        modules(appModule, *platformModules)
    }
}
```

**Step 2: Update `androidApp/src/main/kotlin/dev/viethung/skeleton/android/SkeletonApp.kt`**

**Android Koin boot — keep `startKoin { ... }` directly in `SkeletonApp.kt`.**

Why: `androidLogger(Level.DEBUG)` and `androidContext(this@SkeletonApp)` are Android-specific Koin extensions. Calling them from `commonMain`'s `initKoin()` would pull Android Koin types into the shared module — not allowed.

Update `androidApp/src/main/kotlin/dev/viethung/skeleton/android/SkeletonApp.kt`:

```kotlin
package dev.viethung.skeleton.android

import android.app.Application
import dev.viethung.skeleton.android.di.platformModule
import dev.viethung.showcase.di.appModule
import org.koin.android.ext.koin.androidContext
import org.koin.android.ext.koin.androidLogger
import org.koin.core.context.startKoin
import org.koin.core.logger.Level

class SkeletonApp : Application() {
    override fun onCreate() {
        super.onCreate()
        // CR-02 fix: include platformModule so coreModule can resolve DatabaseDriverFactory.
        // androidLogger + androidContext are Android-only Koin extras that cannot live in
        // shared initKoin() — startKoin is called directly here with the full module list.
        startKoin {
            androidLogger(Level.DEBUG)
            androidContext(this@SkeletonApp)
            modules(appModule, platformModule) // platformModule MUST be present (closes CR-02 for Android)
        }
    }
}
```

The corresponding iOS path lives in Step 3 (AppKoinBridge.swift). The unified narrative: Android uses `startKoin { ... modules(appModule, platformModule) }` directly; iOS uses the shared `initKoin(iosPlatformModule)` from `AppModule.kt`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Koin GlobalContext → ViewModelStore | Factory pattern: appModule registers GreetingRepository/VM as factories (not singletons), so each VM injection creates a new instance — no shared mutable state across injection sites |
| iOS DatabaseDriverFactory → SQLite file | NativeSqliteDriver opens "skeleton.db" in the app's documents directory; no user-supplied path |
| GreetingRepository → AppDatabase | Single reader (selectById); no write path exposed; seed row is immutable at this phase |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Information Disclosure | GreetingRepositoryImpl.getGreeting() | accept | Returns only the seed "Hello, KMP" string; no PII, no user data |
| T-11-02 | Denial of Service | initKoin() called twice | mitigate | Android calls startKoin directly (never calls initKoin()); iOS calls doInitKoin() once from AppKoinBridge.start(); Koin throws KoinAlreadyStartedException if called twice — crash is loud and deterministic, not silent |
| T-11-03 | Elevation of Privilege | IosPlatformModule single { DatabaseDriverFactory() } | accept | No-arg constructor; no external input; creates a SQLite driver for the sandboxed app bundle only |
| T-11-04 | Tampering | iosPlatformModule passed as open array from Swift | accept | The Koin module is compiled Kotlin code; Swift cannot substitute a different Module implementation without recompiling the KMP framework |
</threat_model>
